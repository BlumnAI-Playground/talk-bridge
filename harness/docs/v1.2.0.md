## 요약

샘플 제작·검수에서 실측으로 드러난 CLI/API/문서의 결함·제약이 로그에만 남는 문제를 구조로 해결했다.

**현재 CLI 버전(v1.0.0) 기준 "다음 개선 예고" 스펙** 으로 고정한다. 파트너에게는 한계·우회를, 개선팀에게는 재현·수용 기준이 있는 스펙을 준다.

## 설계 결정

- **디렉터리는 관찰 버전으로**(`v1.0.0/`), 새 버전은 문서 상태만 갱신 — 같은 문서로 "고쳐졌는가" 를 검수하기 위해
- **파일락 결론**: LadybugDB 는 READ_WRITE 하나가 열려 있으면 READ_ONLY 도 못 연다(공식 문서). 게이트웨이가 쓰기 주체인 한 CLI 플래그로는 해결 불가 → "누가 DB 를 여는가" 를 바꾸는 A/B/C 만이 해법
