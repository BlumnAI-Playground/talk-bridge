# 검수 방법론 — 공통 심각도·평가축·보고 형식

> 모든 수행부 에이전트와 엔진이 공유하는 기준. 각 에이전트 정의는 이 문서를 전제로 자기 영역의 체크리스트만 추가한다.

## 1. 검수 대상 범위

| 대상 | 경로 |
|---|---|
| 샘플 서버 | `sample-project/*/server/**/*.js` |
| 헬퍼 스크립트 | `sample-project/*/scripts/*.mjs` |
| 프론트 | `sample-project/*/public/**` |
| 샘플 설정 | `sample-project/*/package.json`, `.env.example`, `.gitignore` |
| 문서 | `README.md`, `docs/*.md`, `sample-project/README.md`, `sample-project/*/README.md` |

`harness/` 자체와 `node_modules/`, `*.png` 는 대상이 아니다.

## 2. 심각도

| 등급 | 정의 | 예 |
|---|---|---|
| **P0 Critical** | 파트너가 그대로 복사하면 보안 사고·데이터 유실·무한 루프가 나는 결함 | 서명 미검증, 시크릿 하드코딩, `agent` echo 미필터 자동응답 |
| **P1 High** | 특정 환경에서 동작 불가 또는 문서와 코드가 어긋나 파트너가 헤매는 결함 | Windows 에서 spawn 실패, README 명령이 `scripts` 에 없음 |
| **P2 Medium** | 동작은 하나 운영 전환 시 문제가 되며 경계 표시가 없는 것 | 인메모리 캡 없음, 오류에 원인만 있고 조치 없음 |
| **P3 Low** | 가독성·일관성·주석 | 오타, 미사용 import |

## 3. 3축 평가 (수행부 공통)

| 축 | 질문 | 등급 |
|---|---|---|
| 코드 안전성 | 그대로 복사해도 보안·신뢰성 계약을 어기지 않는가 | A/B/C/D |
| 아키텍처 정합성 | 문서가 약속한 구조·경계·이식 경로와 일치하는가 | A/B/C/D |
| 테스트 가능성 | `doctor.mjs`·자기검증·재현 절차로 파트너가 스스로 확인할 수 있는가 | A/B/C/D |

A = 결함 없음 또는 P3 만 / B = P2 이하 / C = P1 존재 / D = P0 존재

## 4. 발견 항목 형식

```
[P1] server/cli.js:702 — (한 줄 요약)
  근거: knowledge/talkbridge-cli-spec.md §1
  영향: (누가 어떤 환경에서 무엇을 겪는가)
  제안: (구체적 수정 방향 1~2줄)
```

- 위치는 `경로:줄번호` 로 클릭 가능하게
- **근거는 knowledge/ 문서 또는 원문 문서의 절**을 인용 — 취향이 아닌 계약 위반만 보고
- 결함이 없으면 "확인함" 항목을 짧게 남겨 **무엇을 봤는지** 드러낸다

## 5. 보고서 골격 (엔진 종합 보고)

1. 한 줄 결론 (3축 등급 + P0/P1 개수)
2. 에이전트별 발견 항목 (심각도 내림차순)
3. 확인 완료 항목 (결함 없음)
4. 다음 단계 제안 (수정 우선순위)

## 6. 원칙

- **실제 코드를 읽고** 판단한다. 문서만 보고 추정하지 않는다
- 보고 전에 `harness/logs/{agent|engine}/` 로그를 먼저 남긴다
- 보안 결함의 재현 방법은 방어 목적 범위에서만 기술한다
- 활용 가능한 표준 스킬: `/security-review` (보안 에이전트 보조), `/code-review` (변경 점검 보조) — 결과는 하네스 형식으로 재정리해 보고한다
